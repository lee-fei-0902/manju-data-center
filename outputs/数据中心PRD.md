## 一、背景与现状

### 1.1 业务背景
漫剧平台为团队提供 AI 一站式创作能力，覆盖脚本、角色、镜头、图片、视频等创作全流程。当前平台已沉淀大量**积分消耗数据**与**创作行为数据**，但是：
- 数据散落在项目、抽卡记录、生成结果等多个模块，缺乏**统一汇总入口**。
- 团队管理者（制片人 / 项目负责人 / 小组组长）**无量化视角**评估成员投入与资源消耗。
- 成员自身**无全局视角**看到自己的产出与积分占用情况。

### 1.2 现状痛点
1. **管理者侧**：无法快速回答"这个项目共消耗了多少积分？视频 vs 图片比例如何？谁消耗最多？"。
2. **小组侧**：小组长无法横向对比小组间创作活跃度与资源占用。
3. **成员侧**：创作者无法直观看到个人累计生成时长与抽卡次数，难以复盘效率。
4. **数据透明度**：所有指标以**聚合后再下沉**为原则，与项目、小组、成员三级对应，避免"私账感"。

### 1.3 目标用户与场景

| 角色 | 典型场景 | 关键诉求 |
| :--- | :--- | :--- |
| 项目负责人 | 月度复盘项目投入 | 看到该项目总消耗积分、图片 vs 视频结构、抽卡频次 |
| 小组组长 | 跨项目比较小组产出 | 横向对比创作项目数与积分占用 |
| 普通成员 | 个人周回顾 | 看到自己创作的项目数与积分消耗 |
| 平台运营 | 资源调度 | 监控全量总览（消耗积分、生成时长、抽卡次数） |

## 二、产品目标

### 2.1 业务目标
1. 提供**统一数据中心入口**，使创作资源数据可量化、可追溯。
2. 支持**项目 / 小组 / 成员**三级聚合，覆盖管理侧与创作侧核心视角。
3. 为后续计费、限流、效率分析等能力提供**数据底座**。

### 2.2 体验目标
- 单一入口直达，进入页面 1 秒内可见三大总览指标。
- 一次点击切换 Tab，三个维度数据无刷新即时呈现。
- 数据口径清晰，**每一项指标必须有明确命名与计算规则**，避免歧义。

## 四、用户故事（User Stories）

> 命名规范：作为 [角色]，我希望 [动作]，以便 [价值]。

### 数据中心入口
- **US-01** 作为项目负责人，我希望在工作台右上角看见「数据中心」入口，以便快速进入数据汇总页。
- **US-02** 作为平台运营，我希望入口视觉权重清晰，以便在不影响排行榜使用的前提下识别。

### 数据总览
- **US-10** 作为小组组长，我希望进入数据中心第一时间看到总消耗积分、总生成时长、总抽卡次数，以便快速掌握整体资源占用。
- **US-11** 作为项目负责人，我希望按时间范围筛选总览数据，以便做不同周期的对比。

### 项目模块
- **US-20** 作为项目负责人，我希望看到某项目消耗了多少图片积分、多少视频积分，以便评估该项目的资源结构。
- **US-21** 作为制片人，我希望看到项目的图片抽卡次数与视频抽卡次数，以便评估迭代效率。

### 小组模块
- **US-30** 作为小组组长，我希望横向对比各小组的创作项目数与积分消耗，以便评估小组产能。

### 成员模块
- **US-40** 作为项目负责人，我希望识别消耗积分最高的成员，以便在资源受限场景下优化分配。
- **US-41** 作为成员，我希望看到自己的创作项目数，以便复盘个人产出。

## 五、交互与流程说明

### 5.1 入口流程
```
[工作台工作台页]
        │
        │ 点击「数据中心」(右上角)
        ▼
[数据中心页 / 默认展示「总览」面板]
        │
        │ 点击 Tab: 项目 / 小组 / 成员
        ▼
[切换对应模块列表，保持顶部总览与筛选器]
```

### 5.2 总览区交互
- 进入页面默认展示「**全部时间 / 全部可见项目**」的统计数据。
- 点击卡片右上角 **时间筛选** 下拉，按 7 天 / 30 天 / 自定义范围过滤。
- 切换时间范围后，**总览卡片与下方 Tab 列表同步刷新**。

### 5.3 列表交互
- 列表为**单一表格**结构，行可点击进入详情（详情不在本版本内，留作下一版）。
- 列头支持点击切换**升降序**，默认按第一列业务字段升序降序规则：

| 模块 | 默认排序 |
| :--- | :--- |
| 项目 | 总消耗积分 ↓ |
| 小组 | 创作项目数 ↓ |
| 成员 | 总消耗积分 ↓ |

- 搜索：顶部搜索框，按模块对应字段模糊匹配。

### 5.4 视觉规范
- 沿用工作台**浅灰背景 + 卡片**结构。
- 主色与辅色沿用品牌色（蓝、橙、绿），积分采用橙色 / 数量采用蓝色 / 时长采用绿色加以区分。

## 六、EARS 需求描述

### 6.1 入口（F-01）
- **Ubiquitous**：The system shall 在工作台页面右上角常驻展示「数据中心」入口按钮。
- **State-driven**：While 用户登录态有效，the system shall 渲染该按钮；Else the system shall 隐藏。

### 6.2 总览（F-10 / F-11）
- **Ubiquitous**：The system shall 数据中心页顶部常驻展示三项总览卡片：消耗积分、生成时长、抽卡次数。
- **Event-driven**：When 用户选择新的时间范围，the system shall 同步刷新总览卡片数据与所有 Tab 列表数据。
- **Unwanted**：If 时间范围内没有数据，then the system shall 展示「暂无数据」占位，并保留时间筛选条件。

### 6.3 项目模块（F-20）
- **Event-driven**：When 用户切换至「项目」Tab，the system shall 渲染当前筛选条件下项目列表，包含项目名称与 5 项指标列。
- **Event-driven**：When 用户点击列头，the system shall 切换该列的升降序，并刷新列表。
- **Optional**：Where 列表行支持点击进入项目详情，the system shall 跳转至项目工作台（不在本版本实现）。

### 6.4 小组模块（F-30）
- **Event-driven**：When 用户切换至「小组」Tab，the system shall 渲染当前筛选条件下小组列表。
- **State-driven**：While 默认排序，the system shall 按创作项目数从高到低排列。

### 6.5 成员模块（F-40）
- **Event-driven**：When 用户切换至「成员」Tab，the system shall 渲染成员列表。
- **State-driven**：While 默认排序，the system shall 按总消耗积分从高到低排列。

### 6.6 数据准确性边界
- **Unwanted**：If 同一积分消耗被多次记录，then the system shall 以**最终落库成功**记录为准，并去重失败回执。
- **Unwanted**：If 用户跨项目协作，then the system shall 按**唯一成员维度**聚合，作品计数按其参与过的项目去重计数。

## 七、权限与数据口径

### 7.1 权限矩阵

| 角色 | 总览 | 项目列表 | 小组列表 | 成员列表 |
| :--- | :--- | :--- | :--- | :--- |
| 平台管理员 | 全部数据 | 全部项目 | 全部小组 | 全部成员 |
| 项目负责人 | 全部数据 | 仅其负责项目 | 仅其参与小组 | 仅项目内成员 |
| 小组组长 | 全部数据 | 仅其小组项目 | 仅其负责小组 | 仅小组内成员 |
| 普通成员 | 全部数据 | 仅其参与项目 | 仅其所属小组 | 仅本人 |

> 注：因隐私要求，**总览数据对所有登录用户一致**（业务最终确认可能收紧，详见待确认问题）。

### 7.2 数据口径定义

| 指标 | 计算口径 |
| :--- | :--- |
| 总消耗积分 | Σ 当前筛选范围内所有生成行为消耗积分（含成功与失败重试） |
| 图片消耗积分 | Σ 图片类生成行为消耗积分 |
| 视频消耗积分 | Σ 视频类生成行为消耗积分 |
| 图片抽卡次数 | Σ 图片生成请求成功落库的次数 |
| 视频抽卡次数 | Σ 视频生成请求成功落库的次数 |
| 创作项目数 | 用户 / 小组有创作行为（任意一次成功生成）的项目数，去重 |
| 生成时长 | Σ 所有生成行为从发起至落库成功的耗时（秒） |

## 八、数据指标与监控

| 监控维度 | 指标 |
| :--- | :--- |
| 使用率 | 数据中心入口点击 PV / 工作台 PV |
| 留存 | 7 日内再次访问率 ≥ 30% |
| 数据正确性 | 与计费后台对账差异 ≤ 0.1% |

## 九、上线验收标准（Acceptance Criteria）

1. **AC-01** 工作台右上角稳定可见「数据中心」按钮，点击进入数据中心。
2. **AC-02** 总览卡片在有数据时展示真实数字；无数据时展示「暂无数据」。
3. **AC-03** 切换时间筛选后，总览与列表数据**一致刷新**。
4. **AC-04** 项目 / 小组 / 成员三个 Tab 可正常切换，列表字段与 PRD 第 3 章一致。
5. **AC-05** 数值与计费后台抽样对账，差异 ≤ 0.1%。
6. **AC-06** 权限按第 7.1 节规则生效，越权访问返回 403 / 空数据。
7. **AC-07** 加载性能：首屏 ≤ 1.5s（CDN 内网）。

---

## 十、非功能需求

- **性能**：列表首屏 ≤ 1.5s；大数据量（>1k 行）启用虚拟滚动。
- **国际化**：字段、单位、排序规则支持中英扩展点。
- **可观测**：埋点 `dashboard_visit`、`dashboard_tab_switch`、`dashboard_filter_change`。

## 十一、待确认问题（Open Questions）

1. **总览数据是否对普通成员开放？** 默认全用户可见全部总览，可能涉及商业敏感。
2. **成员列表是否需要脱敏？** 当成员不在当前用户组织时，是否展示「其他成员」聚合行。
3. **时间筛选是否需要支持「按项目周期」？** 当前为系统时间，未考虑项目自有周期。
4. **数据是否需要实时？** 当前按小时聚合可接受，若需实时，需引入流式计算。
5. **历史数据保留策略？** 是否支持查询一年前的数据，保留多长时间的明细。
